## 1. Observation

### Source Code & Configuration Audits
- **`datacontract.yaml`**: The file contains complete definitions for all 9 required tables (`products`, `orders`, `order_items`, `payment_transactions`, `journal_entries`, `journal_lines`, `product_bom`, `memberships`, `membership_transactions`). Properties, types, required/unique fields, and relationships match the frontend/database schema.
- **`scripts/run-datacontract.js`**: Integrates the validation tool using Node's `spawn` to run `datacontract.exe` (or `datacontract` on Unix). It handles cross-platform path checks (local `.venv` path vs global fallback) and sets the environment variable `PYTHONIOENCODING=utf-8` to prevent Windows terminal encoding crashes.
- **`src/lib/systemDataAudit.ts`**: Implements detailed offline data integrity audit rules (e.g., comparing product stock to warehouse totals, checking negative stock, checking price-to-cost deviations, verifying payment details against orders, flagging duplicate transactions, testing Nợ/Có ledger balancing, matching BOM costs, verifying membership wallet balances against transaction history). No hardcoding, facade, or dummy logic was found in the checks; they compute and assert dynamically on snapshots.
